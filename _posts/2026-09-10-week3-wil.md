이름은 다이나믹한데, 개념 이해는 다이나믹하지 않았다. 정말 많이 헷갈렸다. BFS, DFS나 뭐 재귀, 뭐 어쩌고 이런 거는 약간 나누어져 있고 템플릿이 있는 개념이었는데, DP는 방법론이다 보니...이해를 위해서 Leetcode에 있는 DP Easy 13문제 정도를 계속 풀기도 했었는데, 다 풀고 나서도 "그래서 DP가 뭐지?" 라는 생각밖에 안들었다. 옛날에도 "DP는 어려운 것이다." 라는 생각이 있었으니...

그래도 최대한 이해한 선에서, 복습을 할려고 한다.

## 다이나믹 프로그래밍

### 이 뭘까...

> 작은 문제의 답을 구하고, 그 답을 다시 활용해서 더 큰 문제를 해결하는 알고리즘 설계 방법. 
> 같은 작은 문제를 매번 다시 풀지 않는 것이 핵심이다.

작은 예시 문제를 하나 들자.

> "1원, 3원, 4원짜리 동전이 각각 무제한으로 있다. 정확히 6원을 만들 때 필요한 최소 동전 개수는 얼마일까?"

만약 내가 풀었으면, 이렇게 풀었을 것이다.

```text
	1 + 1 + 1 + 1 + 1 + 1 = 6원 -> 동전 6개
	3 + 1 + 1 + 1 = 6원 -> 동전 4개
	4 + 1 + 1 = 6원 -> 동전 3개
	3 + 3 = 6원 -> 동전 2개
```

"3원 두 개면 6원을 만들 수 있으니, 동전 2개가 답이다."

사실 무지성으로 큰 동전부터 쓰면 `4 + 1 + 1` 이므로 오답이다. 그런데, 6원이 아니라 12원이면? 20원이 되면? 1,000,000원(사실 백 만원을 동전으로 만들려는 거 자체가 좀...)이 되면? 모든 Case를 다 써가면서 규칙을 찾아야 할 텐데, 그러고는 싶지 않았다. 

그렇다면 생각을 바꾸어서

`6원을 만드는 답을 바로 모르더라도, 다른 금액의 답을 알고 있으면 도움이 되지 않을까?`

라고 해보자.

그렇다면, 메모리를 써서 먼저 무엇을 저장할 지 정하자.

> 배열을 하나 선언해서, 인덱스를 "금액" 으로 놓고, 이 금액을 만들 때 필요한 최소 동전 개수를 저장해놓자.
> `dp[x]` = **정확히 x원을 만드는데 필요한 최소 동전 개수**

`x`는 금액, `dp[x]`는 동전 개수. 그러면 6원을 만들때의 답은 다음과 같이 될 것이다.

```text
	dp[1] -> 1원을 만드는 데 동전이 최소 몇 개 필요한가?
	dp[2] -> 2원을 만드는 데 동전이 최소 몇 개 필요한가?
	dp[3] -> 3원을 만드는 데 동전이 최소 몇 개 필요한가?
	...
	dp[6] -> 6원을 만드는 데 동전이 최소 몇 개 필요한가?
```

그러면 답은 정해졌다.

`dp[6]을 구하면 되겠네?`

하지만, 

`그런데 dp[6]은 어떻게 구하지?`

### 마지막에 뭘 썼지?

일단 마지막에 쓴 동전이 무엇인지 한 번 가정해보자.

> 1원짜리 동전을 썼다면, 그 전에 5원을 만들어놨을 것.
> 3원짜리 동전을 썼다면, 그 전에 3원을 만들어놨을 것.
> 4원짜리 동전을 썼다면, 그 전에 2원을 만들어놨을 것.

이를 만들어놓은 `dp[]`로 표현하면,

> `dp[5] + 1`
> `dp[3] + 1`
> `dp[2] + 1`

그렇다면 관계식은 다음과 같이 만들 수 있을 것이다. 이 세 가지 중 가장 최소인 것이, `dp[6]`을 만들때 필요한 최소 동전 개수일 것이다.

```text
	dp[6] = min(
		dp[5] + 1,
		dp[3] + 1,
		dp[2] + 1
	)
```

이런 식으로 "문제의 답을 작은 문제의 답과 연결한 식"을 **점화식**이라고 생각하면 된다. 최적화 문제에서 **작은 문제의 최적 답을 이용해 전체의 최적 답을 구성할 수 있는 성질**을 "최적 부분 구조" 라고 한다.

하지만, 비슷한 문제가 남아있다.

`dp[5]가 뭐고, dp[3]이 뭐고, dp[2]가 뭐지?` 

### 쉬운 것부터 차근차근

지금은 너무 위에서 찾고 있으니, 아래에서 쉬운 것부터 먼저 구해야한다.

> "0원을 만드는 데 동진이 몇 개 필요한가?"
> `dp[0] = 0` 

0원을 만드는 것은 0개가 필요하다.
이를 Basis, "기저값"이라고 한다. 여기서부터 올라가보자.

```text
	dp[0] = 0
	dp[1] = dp[0] + 1
	dp[2] = dp[1] + 1
	dp[3] = min(dp[2] + 1, dp[0] + 1)
	dp[4] = min(dp[3] + 1, dp[1] + 1, dp[0] + 1)
	dp[5] = min(dp[4] + 1, dp[2] + 1, dp[1] + 1)
	dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1)
```

이렇게 써보니, 이제 `dp[5], dp[4], dp[3]...` 을 알 수 있게 되었고, 따라서

`dp[6] = min(2 + 1, 1 + 1, 2 + 1) = 2`

6원을 만드는데는 3원 짜리 두 개의 동전이 필요하다라는 답을 알 수 있게 되었다.

이렇게 필요한 작은 문제들을 먼저 계산하고, 그 결과로 더 큰 문제를 계산하는 구현 방식을 "Bottom-Up" 방식이라 부른다. 그리고 이렇게 같은 작은 문제가 반복해서 나타나는 것을 "중복 부분 문제" 라고 한다. 이 계산 결과를 저장해서 재사용하면, 중복 계산을 줄일 수 있다.

해당 문제를 이제 코드로 옮긴다면,

```python
	coins = [1, 3, 4]
	target = 6
	
	# dp[amount]: amount원을 만드는 데 필요한 최소 동전 개수
	# 1원 동전이 있으므로 정답은 최대 target개입니다.
	# target + 1은 아직 답을 구하지 않았다는 표시로 사용합니다.
	dp = [target + 1] * (target + 1)
	
	dp[0] = 0
	
	for amount in range(1, target + 1):
	    for coin in coins:
	        if coin <= amount:
	            candidate = dp[amount - coin] + 1
	            dp[amount] = min(dp[amount], candidate)
	
	print(dp[target])  # 2
```

## 저장과 활용

DP는 단순히 "저장하는 것"이 아닌,

```text
	큰 문제의 답을 작은 문제의 답으로 표현하고,
	그 작은 문제들의 답을 저장해서 다시 활용하는 것.
```

첫 번째로 생각할 건,

> "무엇의 답을 저장할까?"

두 번째로 생각할 건,

> "마지막 선택 하나를 정하면 무엇이 남을까?"

세 번째로 생각할 건,

> "어디서 출발하고, 어떤 순서로 계산할까?"

어렵다. DP는 확실히 느낀건데, 많이 풀어봐야겠다. 그래야 이 세 가지를 세우는 것을 좀 연습할 수 있겠다라고, 정말 깊이 생각하고 있다.
